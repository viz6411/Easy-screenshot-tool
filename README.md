# Easy screenshot tool

Отдельная программа для Windows: выделить область (или окно) на экране → подписать её
стрелками/текстом/фигурами → сохранить PNG или положить в буфер обмена. Написана с нуля,
самостоятельная, ничего не устанавливает кроме самого exe. Готовый файл тоже можно открыть и
подписать: `ShotMvp.exe снимок.png`.

Это не надстройка над чужим скриншотчиком: в приложении нет ни одного чужого ассета, ни одной
чужой библиотеки. Иконки на тулбаре нарисованы геометрией в коде, шрифты — системные.

## Из чего собрано

| слой | чем |
|---|---|
| приложение | C++17, Win32, один translation unit (`src/main.cpp` + заголовки) |
| рисование редактора | Direct2D 1.0 + DirectWrite (piлюля, иконки, текст, превью аннотаций) |
| захват экрана | GDI: `BitBlt` с `CAPTUREBLT`, `PrintWindow`, `GetDIBits` |
| вывод | PNG через GDI+ (`gdiplus`) и буфер обмена (CF_DIB / CF_DIBV5) |
| тесты | Python + ctypes. Только измерение и ввод; в сам exe не входит ничего python'ового |

Приложение — C++. Python в репозитории существует только как измерительный щуп: он читает
пиксели с экрана и дёргает настоящие мышь/клавиатуру, чтобы проверять, что нарисовано там же,
где и кликается. Производительность интерфейса (захват, отрисовка, аннотации) — целиком C++.

## Сборка

Нужен MinGW-w64 `g++` (C++17) и `windres` (он же в составе MinGW-w64), Python 3 — только для тестов.

```powershell
pwsh .\build.ps1            # build\ShotMvp.exe + build\ShotMvp_console.exe
pwsh .\build.ps1 -Selftest  # и сразу встроенная диагностика
```

`build.ps1` делает две вещи, которые важно не пропустить:

1. `-municode -DUNICODE -D_UNICODE` — без них не линкуется точка входа `wWinMain` и ломаются
   wide-строки в `LoadCursorW`.
2. `windres src\app.rc` — компилирует манифест `src\app.manifest` (`dpiAware=true`,
   `dpiAwareness=PerMonitorV2`) как ресурс `RT_MANIFEST` id 1 и линкует его в оба exe. Раньше
   манифест подменялся правкой готового бинарника (`tools\replace_manifest.py`, карточка #18) —
   этот шаг убран, источник манифеста лежит в репозитории.
   Без манифеста Windows виртуализует координаты при масштабе экрана ≠ 100 %: оверлей перестаёт
   покрывать физический экран, а редактор считает размеры пилюли по чужому числу и рисует кашу.

## Запуск

```powershell
build\ShotMvp.exe
```

После запуска приложение висит в фоне и ждёт хоткей (настраивается в `settings.ini` рядом с exe,
создаётся сам при первом запуске):

| действие | по умолчанию |
|---|---|
| выделение области | `Ctrl+Shift+P` |
| снять активное окно | `Ctrl+Shift+W` |

Если комбинация занята другим приложением, подбирается запасная из списка и честное сообщение
об этом показывается; фактически работающая комбинация сохраняется в `settings.ini`, чтобы UI и
настройки не расходились.

`settings.ini`:

```ini
hotkey=Ctrl+Shift+P
hotkey_window=Ctrl+Shift+W
save_dir=C:\Users\viz\Desktop
name_format=screenshot_%Y-%m-%d_%H-%M-%S
```

Режимы для диагностики и тестов:

```
ShotMvp.exe -selftest              диагностика DPI, оверлея, захвата (печает результат)
ShotMvp.exe -grab -region          один захват области, без настройки хоткеев
ShotMvp.exe -grab -window          один захват окна под курсором
ShotMvp.exe -grab -rect x,y,w,h    захват фиксированной области (для автотестов, без оверлея)
ShotMvp.exe C:\path\shot.png       открыть готовый PNG в редакторе
```

## Что в редакторе сейчас

Тёмная парящая пилюля по центру сверху; ниже — снятые пиксели; внизу — полоса статуса с
размером области и подсказкой по клавишам.

Пилюля, слева направо: стрелка, текст, прямоугольник, овал | маркер, кадрирование | 7 цветов |
3 толщины линии | отменить, повторить, копировать, сохранить.

Состояния контролов: обычный, под курсором, активный (акцентная обводка и подложка), нажатый,
неактивный (утопленный — например «отменить» пустой или «сохранить», когда правок нет). `Esc` и
крестик закрывают редактор; при несохранённых правках закрывание спрашивает
«Сохранить / Не сохранять / Отмена», и пока правки не выведены, в подписи группы вывода видно
«есть несохранённые правки». `Ctrl+Z` / `Ctrl+Y` / `Ctrl+S` / `Ctrl+C` работают.

### Размер окна, перестроение панели, DPI

Панель не обрезается при изменении размера окна, а перестраивается: пять групп переходят на две и
на три строки, текстовые подписи снимаются раньше, чем контролы уйдут за край. План выбирается по
ширине **и** по высоте, поэтому тулбар не может накрыть полосу статуса. Снимок и штрихи обрезаны
полосой между тулбаром и полосой статуса; начать рисовать вне видимой полосы нельзя. Окно нельзя
сжать ниже размера, который раскладка ещё умеет нарисовать (при 175 % это 596×355 px, и пилюля
занимает в нём 512 из 572 px клиента). Замеры раскладки пересчитываются при смене DPI и при
переносе окна на другой монитор. Порядок деградации и числа — `docs\TOOLBAR-SPEC.md` §9.

## Проверки

```powershell
python tests\stage1_states.py        # приёмка панели: геометрия, состояния, клики, полоса статуса
python tests\stage2_behaviour.py     # поведение: текст, кадрирование, история, вывод (#5-#8)
python tests\stage3_open_png.py      # открытие готового файла, целостность и вес PNG (#16 #17)
python tests\stage4_unsaved.py       # несохранённые правки: три ответа при закрытии, индикатор (#22)
python tests\stage5_layout_resize.py # матрица из 12 размеров окна, инварианты раскладки (#24)
python tests\dpi_verify.py           # оверлей покрывает физический экран целиком
build\ShotMvp.exe -selftest          # DPI-осведомлённость, метрики экрана, захват
```

`tests\stage1_states.py` запускает настоящее приложение с фиксированной областью, затем настоящей
мышью наводит курсор, кликает, рисует аннотацию и жмёт «сохранить», а после считает пиксели,
которые реально оказались на экране. Группы проверок:

- **A геометрия** — пилюля отцентрована, контролы одной ширины и на одном шаге, свотчи
  квадратных цветов, ничего не вылезает за пилюлю, снятая область = 1120×700 физических пикселей;
- **B состояния** — активный инструмент ровно один, активная толщина одна, «отменить/повторить»
  выглядят неактивными, «копировать/сохранить» — активными;
- **C попадание** — клик по тому месту, где контрол нарисован, активирует именно его, соседние
  не активируются, наведение меняет подложку, но не активирует;
- **D полоса статуса** — своя линия-разделитель, текст под ней, изображение её не касается;
- **E сквозная** — нарисованная аннотация видна на снимке, «сохранить» создаёт файл ровно размера
  снятой области, в буфере обмена битмап того же размера и аннотации запечены в пикселях.

`tests\stage5_layout_resize.py` меряет раскладку тем же способом: панель находится по её собственной
поверхности, контролы — по залитым квадратам контрольной поверхности, картинка открывается из
заранее известного PNG (magenta/cyan), чтобы пиксели рабочего стола не принимались за контролы
приложения. Размер окна меняется через `SetWindowPos`, весь ввод — post'ом в окно приложения.

Все размеры тест измеряет по факту на экране, а не по константам из кода: проверка работает при
любом масштабе дисплея.

## Релиз

```bash
python3 tools/release.py v0.2.1 --milestone "0.2.1 - устойчивость UI: размер окна, DPI, аккуратная раскладка"
```

Скрипт проверяет чистоту дерева и совпадение `HEAD` с `origin/main`, экспортирует релизный коммит в
отдельную поставку, собирает её `build.ps1 -Selftest` на собирающей машине (без `SELFTEST PASSED`
релиз не состоится), прикладывает к релизу `ShotMvp-<версия>.exe` и `ShotMvp_console-<версия>.exe`
с размером и SHA-256 в теле релиза и закрывает milestone. Причина — карточка #23: `v0.2.0` был
выпущен с пустым списком вложений.
