# Чеклист приёмки Easy-screenshot-tool

Владелец файла — tester. Пункт = проверка действиями живого пользователя, а не список фич.
Формат: `кто / где / действие → что видно глазами`. Пункт закрывается только если результат
видно глазами на реальной сборке. Протокол осмотра: экран 2560x1600 @ 175%, тёмная тема,
окна браузера и проводника частично перекрывают рабочий стол, в буфере обмена есть чужая картинка.

## Веха 0.2 — быстрый фикс-релиз

### Захват
1. Пользователь / рабочий стол / сочетание клавиш захвата области (настраивается в приложении) → экран затемняется, появляется рамка выделения с подписью размера; после отпускания мыши открывается редактор со снимком этой области.
2. Пользователь / рабочий стол / оконный хоткей → снимок активного окна, редактор открыт на этом снимке, рамка окна не обрезана.
3. Пользователь / редактор / снять область в нижней и правой части экрана (до самых краев) → в редакторе видно ровно то, что было на экране; правый нижний край не срезан, размер в подписи = размер области в физических пикселях.
4. Пользователь / редактор / снять область через границу двух мониторов с разным масштабом → снимок не растянут и не сжат, картинка 1:1 к экрану.

### Панель инструментов
5. Пользователь / редактор / посмотреть на панель → все контролы панели видно: у каждого инструмента и у действий вывода есть текстовая подпись; группы разделены видимым зазором и разным фоном.
6. Пользователь / редактор / посмотреть на каждый значок (увеличенный лист `docs/icons/`) → значки читаются как стрелка, текст, прямоугольник, овал, маркер, кадрирование, отмена, повтор, копировать, сохранить; ничего «просто линии» и «просто прямоугольника» среди них нет.
7. Пользователь / редактор / навести курсор на контрол → у контрола появляется подсветка; нажатие и отпускание внутри контрола не активирует соседний.
8. Пользователь / редактор / кликнуть по контролу, нарисованному слева от того, куда попала мышь → активен ровно тот контрол, под курсором которого находится кликабельная область.
9. Пользователь / редактор / кликнуть по свотчу цвета → у свотча появляется кольцо акцента, форма свотча не меняется, последующая линия этого цвета.
10. Пользователь / редактор / выбрать толщину → выбранный образец толще остальных, линия на снимке соответствует выбранной толщине.

### Инструменты и правки
11. Пользователь / редактор / выбрать инструмент «текст» и кликнуть по снимку → в точке клика появляется курсор ввода, набранный с клавиатуры текст виден на снимке.
12. Пользователь / редактор / ввести текст и выбрать цвет текста и подложку (светлая / тёмная / нет) → текст читается на любом фоне выбранного цвета; подложка «нет» не рисует прямоугольник.
13. Пользователь / редактор / выполнить кадрирование, затем Ctrl+Z → кадрирование отменено, снимок вернулся в исходный размер, правки аннотаций не потеряны.
14. Пользователь / редактор / Ctrl+Y после Ctrl+Z → правка возвращена на место.
15. Пользователь / редактор / нарисовать стрелку и овал, затем дважды Ctrl+Z и дважды Ctrl+Y → порядок отмен и повторов соответствует порядку действий.

### Вывод результата
16. Пользователь / редактор / «Копировать» → в буфере обмена изображение; в папке сохранения новый файл не появился; редактор не закрылся.
17. Пользователь / редактор / «Сохранить» → появляется выбор места (папки) и имени; после подтверждения файл создан в выбранном месте; открытая копия соответствует снимку с аннотациями.
18. Пользователь / редактор / есть несохранённые правки → закрытие редактора задаёт вопрос (сохранить / не сохранять / отмена); «не сохранять» ничего не пишет на диск; «отмена» оставляет редактор открытым.
19. Пользователь / редактор / посмотреть в нижнюю часть окна → полоса статуса не перекрывает снимок; между рамкой снимка и полосой есть зазор; в полосе видны размер снимка и подсказка по горячим клавишам.

### Общее
20. Пользователь / приложение / настройки хоткея в самом приложении (а не в файле) → новый хоткей работает сразу; старый не перехвачен другим приложением; значение переживает перезапуск.
21. Пользователь / редактор / увеличить и уменьшить масштаб (если контрол уже есть) → размер буфера снимка не меняется, экспорт остаётся в исходном разрешении.

## Метрика

Escape rate: сколько дефектов найдено проверками до релиза против сколько найдено владельцем после
релиза (цель ≤ 2). Каждый дефект владельца порождает: пункт этого чеклиста, регрессионный автотест
и запись в памяти проекта. Ссылка на «сколько прогонов сделано» как показатель качества запрещена.
