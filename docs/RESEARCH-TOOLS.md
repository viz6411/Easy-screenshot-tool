# Карта интерфейса исходной скриншотилки

Наблюдение за тем, как устроена скриншотилка Yandex Disk 4 (`YandexDiskScreenshotEditor.exe`),
чтобы наш инструмент был с ней по функционалу, а не по памяти и не по догадкам.

Никаких файлов, иконок, картинок и кода оригинала здесь нет: только описание структуры и
поведения. Кадры наблюдения (скриншоты их интерфейса) не коммитятся - на них виден рабочий
экран владельца компьютера; они остаются локально в `screenshot_mvp/yd_out/`.

## 1. Как наблюдение проводилось

1. Редактор запущен напрямую: `C:\Program Files\Yandex\YandexDisk4\YandexDiskScreenshotEditor.exe`
   (на этом ПК также установлен и запущен более старый клиент 3.2.51.5210 в
   `AppData\Roaming\Yandex\YandexDisk2\` - наблюдался именно редактор из `YandexDisk4`, как и
   договорились).
2. Структура окна читалась стандартными оконными вызовами: перечисление окон процесса,
   перечисление дочерних контролов (класс, текст, геометрия), отрисовка отдельных контролов в
   картинку для чтения глазом.
3. Меню читалось как настоящее меню Win32: `GetMenu` / `GetMenuItemCount` / `GetMenuStringW` -
   то есть пункты меню ниже приведены дословно, а не на глаз.
4. Кнопки нажимались сообщениями окну (`BM_CLICK`, `WM_LBUTTONDOWN/UP`), курсор мыши для этого
   не двигался. Два нажатия курсором в начале всё-таки были сделаны и попали не в их окно, а в
   окно браузера поверх - описано в разделе «Ошибки метода».
5. Закрывали редактор кнопкой «Don't save» в его собственном диалоге. Ни один файл на диск
   сохранён не был (проверено по списку файлов на рабочем столе).

## 2. Точка входа: сначала выбор режима

Запуск без аргументов открывает не оверлей, а окно выбора (814x688 px, заголовок
«Yandex Disk screenshot editor») с четырьмя действиями:

| Действие | Что делает |
|---|---|
| Area | выделяет область экрана |
| Window | снимает окно под курсором |
| Fullscreen | снимает весь экран |
| Open file | открывает уже существующий файл в редакторе аннотаций |

Вывод для нас: режимы съёмки - это отдельные пути, а не одна кнопка. У нас сейчас есть Area
(оверлей) и Window (флаг `-window`), режим «весь экран» и «открыть файл» не сделаны (карточка
«Открытие готового файла - заглушка»).

## 3. Анатомия окна редактора

Максимизированное окно (2584x1540 px physical при экране 2560x1600 и масштабе 175 %), заголовок
имени файла: `2026-11-13_20-23-09.png - Yandex Disk`. Внутри - четыре горизонтальные полосы:

| Полоса | Высота (px) | Что в ней |
|---|---|---|
| строка меню (File / Edit / View) | 28 px клиентской области | настоящее меню |
| полоса инструментов | 66 | инструменты + отмена/повтор |
| полоса свойств выбранного инструмента | 60 | подтипы инструмента, толщины, цвета |
| полотно снимка | 1248 | изображение |
| нижняя полоса | 68 | масштаб слева, действия вывода справа |

Контролы полосы свойств: высота 40 px, ширина кнопок 66-145 px. Для сравнения: у нас контрол
пилюли 32 логических px (56 px physical при 175 %), то есть наши кнопки заметно крупнее их.

## 4. Полоса инструментов

Инструменты собраны в две группы по три кнопки плюс отдельная группа действий вывода:

- группа слева: 3 кнопки шириной 80 / 79 / 79 px;
- группа правее: 3 кнопки шириной 66 / 68 / 66 px;
- группа справа: 8 квадратных контролов 39-40 px (это палитра цветов - по виду круглые свотчи);
- отдельно в той же полосе нарисованы «отменить» и «повторить» (их нет в перечне дочерних
  контролов - они отрисованы самой полосой, не отдельными окнами).

Названия инструментов в их полосе подписаны текстом рядом с пиктограммой (подписи читались по
кадру: `Arrows`, `Text`, `Shapes`, `Marker`, `Blur`, `Crop`). Подпись обязательна - одна
пиктограмма у них не используется.

## 5. Полоса свойств: она меняется под инструмент

В строке свойств живёт шесть разных групп; одновременно показаны только относящиеся к выбранному
инструменту, остальные скрыты (но существуют как контролы - это видно по перечню):

| Группа | Кнопки (ширина x высота) | Статус при наблюдении |
|---|---|---|
| 248 px | 80, 79, 79 | показана |
| 210 px | 66, 68, 66 | показана |
| 313 px | 40, 39, 39, 39, 39, 39, 39, 39 (свотчи) | показана |
| 343 px | 79, 109, 145 | скрыта |
| 275 px | 65, 65, 65, 65 | скрыта |
| 159 px | 68, 81 | скрыта |
| 132 px | 40, 40, 40 | скрыта |

Прочитанное глазами по активному инструменту «стрелки»:

- три стиля стрелки: сплошная широкая, тонкая контурная, пунктирная «след»;
- три толщины линии: тонкая, средняя, жирная (показаны волнистыми штрихами разной толщины);
- восемь цветов в палитре (тёмный, белый, синий, жёлтый, красный, зелёный, фиолетовый, серый).

Скрытые группы - это полосы свойств *других* инструментов: у группы 275 px четыре кнопки одинаковой
ширины 65 px (похоже на набор текстовых настроек), у группы 343 px кнопки 79/109/145 px (широкие -
значит с подписями), у 159 px всего две кнопки (похоже на пару «применить/отменить» при кадрировании),
у 132 px три квадратные кнопки по 40 px (набор фигур). Точное содержимое этих групп не подтверждено
(см. раздел «Ошибки метода») - это наблюдение по геометрии, а не по прочитанным подписям.

## 6. Нижняя полоса: масштаб и вывод

Слева - группа масштаба шириной 348 px: блок 58 px (текущий масштаб, при наблюдении `70 %`),
кнопка 28 px (уменьшить), полоса-регулятор 224 px, кнопка 28 px (увеличить). Подтверждение, что
масштаб - полноценная функция: в меню `View` есть `Zoom in` и `Zoom out`.

Справа - действия вывода, каждое подписано текстом: `Copy`, `Save`, `Share` (и у `Save` вид
«неактивной» кнопки, когда нечего сохранять).

## 7. Меню (дословно, прочитано из меню Win32)

- `File`: `Open...`, `Save and exit`, `Share and exit`, `Copy screenshot and exit`,
  `Page setup...`, `Print...`, `Settings`, `Exit`
- `Edit`: `Undo`, `Redo`, `Cut`, `Copy`, `Paste`, `Delete`
- `View`: `Zoom in`, `Zoom out`

Выводы для нас:

1. Вывод результата у них сформулирован как действие + выход: «сохранить и выйти»,
   «скопировать и выйти». Это их способ решить вопрос «что делать с несохранённым».
2. `Cut`, `Copy`, `Paste`, `Delete` в `Edit` - это про работу с выделенным объектом аннотации:
   без выделения объекта (карточка «Нельзя редактировать уже нарисованные аннотации») эти пункты
   не имеют смысла.
3. `Settings` живёт в меню `File`, а не в отдельном окне при запуске.

## 8. Диалог при закрытии с несохранённым

При попытке закрыть редактор с несохранёнными правками их окно спрашивает:

> Save / Don't save / Cancel, плюс кнопка «Don't ask again»

То есть поведение «что делать с несохранённым» - настраиваемое и объясняется в самом диалоге.
Это ровно то место, где мы сейчас молча решаем за пользователя (у нас: Esc - выбросить,
«Сохранить» - файл, «Копировать» - буфер). Относится к карточке «Сохранение: выбор папки
назначения; копирование: только буфер обмена».

## 9. Карта паритета: инструмент -> подтипы -> параметры -> где это у нас

| Инструмент оригинала | Подтипы (наблюдено) | Настраиваемое | Наш статус |
|---|---|---|---|
| Стрелки | сплошная широкая, тонкая контурная, пунктирная «след» | стиль, толщина (3 значения), цвет | есть один стиль стрелки, 3 толщины, 7 цветов; подтипов нет |
| Текст | - | цвет текста, подложка (светлая/тёмная/нет), шрифт, размер | рисуется только drag'ом, без подложки и настроек |
| Фигуры | прямоугольник, овал, звезда (по пиктограмме группы) | цвет заливки, цвет обводки | есть прямоугольник и овал, обводка одна на всех |
| Маркер | - | ширина (их ключ `MarkerWidth`), цвет (`MarkerColor`) | есть, без настроек ширины |
| Размытие | - | сила/область | пиктограмма есть, инструмента нет |
| Кадрирование | - | цвет рамки (`CropColor`), автообрезка прозрачных краёв (`TransparentAutoCrop`) | есть, не отменяется (`Ctrl+Z`), настроек нет |
| Действия вывода | - | Copy / Save / Share, поведение при закрытии | Copy и Save есть без подписей, Share и Print нет |
| Масштаб | Zoom in / Zoom out + регулятор | процент (наблюдено 70 %) | отсутствует |
| Съёмка | Area / Window / Fullscreen / Open file | - | Area и Window есть, Fullscreen и Open file нет |

## 10. Ошибки метода (чтобы не выдавать догадку за факт)

1. Два нажатия мышью по координатам в начале работы пришли не в окно редактора, а в окно браузера,
   которое было поверх. Это могло оставить побочный клик в чужом окне - в дальнейших шагах мышь не
   использовалась вообще, только сообщения контролам.
2. Их кнопки инструментов - не стандартные Win32-кнопки, а собственные контролы (`WTL_BitmapButton`).
   `BM_CLICK` и сообщения о нажатии мыши на них не вызвали смену полосы свойств: шесть попыток
   нажатия дали ровно тот же набор видимых групп. Поэтому содержимое полос «Text / Shapes / Marker /
   Blur / Crop» подтверждено только геометрией скрытых групп и названиями сохранённых настроек
   (`LineStyle`, `ArrowWidth`, `Width`, `FontName`, `FontSize`, `FontColor`, `TextBgColor`,
   `ShapeToolName`, `OutlineColor`, `CropColor`, `MarkerWidth`, `MarkerColor`, `TransparentAutoCrop`),
   а не прочитанными подписями.
3. Названия подтипов стрелок («сплошная / контурная / пунктирная») - наше описание увиденной
   графики, их внутренние имена неизвестны.
4. Список из восьми цветов прочитан глазами; их точные значения не измерялись.

## 11. Что делаем с этим знанием

1. Полоса инструментов обязана быть подписанной: пиктограмма + название инструмента. Одна
   пиктограмма без подписи - то, за что справедливо ругают наш теперешний интерфейс.
2. Инструменты делятся на группы, и у выбранного инструмента появляется своя полоса свойств с
   подтипами. Одна общая полоса на все инструменты - не паритет.
3. Действия вывода (`Копировать`, `Сохранить`) получают подписи и состояние «нечего сохранять».
4. Масштаб - отдельная функция с видимым процентом, уменьшением и увеличением; без неё паритета
   не будет (карточка «Нет зума изображения в редакторе»).
5. Вопрос несохранённого результата решается явным диалогом с вариантами «сохранить / не сохранять
   / отменить», а не молча.
