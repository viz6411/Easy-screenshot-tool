# Дизайн-система редактора

## Направление

Тёмная парящая пилюля с инструментами сверху, снимок под ней, полоса статуса внизу. Референсы,
по которым выбран этот вид: CleanShot X (пилюля и спокойные состояния контролов), Flameshot
(инструменты у самого выделения), Snagit и ShareX (полоса свойств + вывод), Windows 11 Snipping
Tool (родные для системы радиусы, акцент и подписи).

Пилюля не приклеена к рамке окна и не выглядит как панель Win32: у неё свой радиус, своя
подложка и своё расстояние до снимка. Никаких «невидимых кнопок»: у контрола всегда есть
подложка, граница и подпись состояния, и они рисуются тем же кодом, который потом принимает
клик (см. «Один источник истины»).

## Токены

Базовые поверхности (`src/theme.h`):

| токен | значение | где |
|---|---|---|
| `canvas` | `#1A1C20` | фон редактора вокруг снимка |
| `floating` | `#212429` | подложка пилюли |
| `control` | `#363D47` | подложка контрола в обычном состоянии |
| `controlHover` | `#424A56` | подложка под курсором |
| `controlPressed` | `#4C5561` | подложка при нажатии |
| `borderSoft` | белый 7 % | разделители групп, тихие обводки |
| `borderStrong` | белый 14 % | обводка контрола и волосковая рамка снимка |
| `focusRing` | белый 30 % | кольцо фокуса |

Текст: `#ECF0F4` основной, `#ABB3BE` вторичный, `#7E8794` третичный, `#5C6471` приглушённый.

Акцент берётся из системы (`DwmGetColorizationColor`) и при необходимости осветляется, чтобы
читать себя на тёмной подложке. Акцент — это состояние интерфейса (активный контрол, кольцо,
подсветка кадрирования). Красный `#E42A31` остаётся цветом *аннотаций*: он цвет содержимого, а не
интерфейса, и путаться с акцентом не должен.

## Масштаб

Всё в системе кратно `k = dpi / 96`. Сетка отступов `s2 … s24`, высота контрола `32·k`,
внутренний отступ пилюли `s6`, padding вокруг снимка `s12`, радиус пилюли `12·k`, радиус
контрола `6·k`. Ни одного «магического» числа в пикселях: меняя только `dpi`, интерфейс
пересобирается целиком, и проверка `WM_DPICHANGED` пересчитывает тему на лету при перетаскивании
окна на другой монитор.

## Состояния контролов

`ST_NORMAL` → подложка `control`, граница `borderSoft`.
`ST_HOVER` → подложка `controlHover`.
`ST_ACTIVE` (выбранный инструмент/толщина/цвет) → подложка с акцентом и граница акцента 1.5 px.
`ST_PRESSED` → `controlPressed`.
`ST_DISABLED` (например «отменить», когда отменять нечего) → подложка цвета `canvas`, то есть
контрол выглядит утопленным, а не «серым квадратом».

## Анатомия пилюли

```
стрелка  текст  прямоугольник  овал │ маркер  кадрирование │ 7 цветов │ 3 толщины │ отменить повторить копировать сохранить
```

Группы разделены тихой линией с воздухом по бокам. Цвета — квадратные свотчи 22·k со скруглением
5·k; те из них, что близки к цвету самой пилюли (почти чёрный, белый), получают усиленную
границу, иначе свотч визуально сливается с подложкой и выглядит дыркой. Толщины показывают себя
как чертёж: линия той же толщины и того же цвета, которым сейчас будет рисовать.

## Один источник истины

`layout()` один раз считает список слотов (тип, идентичность, геометрия). Из этого списка
рисуются пилюля, иконки, свотчи и полоса статуса; из того же списка работает проверка попадания
мыши и горячие клавиши. Поэтому расхождение «нарисовано здесь, а кликается там» невозможно по
конструкции — в MVP №1 именно это и было сломано, и автотест C теперь это проверяет.

## Что должно стать фирменным приёмом (этапы 2–4)

1. **Измерение во время рисования**: лупа 8× у курсора и живой HUD размеров/угла рядом с рамкой
   выделения — выделение должно говорить, сколько пикселей ты берёшь, а не показывать это потом.
2. **Пилюля свойств, привязанная к объекту**: параметры стрелки или текста висят у самого
   объекта, а не в верхней панели, и не закрывают содержимое.
3. **Спокойный вывод**: после сохранения — короткая полоса «куда положил», без модальных окон.

Слои глубины держатся на двух приёмах: граница вместо тени и ramp поверхностей (canvas →
floating → control). Теней, бликов и стекла нет.
