# ShotMvp — план доведения до паритета и выше

Документ для поэтапной приёмки. Каждый этап заканчивается **артефактом, который ты смотришь
глазами** (скриншот реального окна) + автотестом. Этап не считается сделанным, пока артефакт
не принят.

---

## 0. Что уже есть и почему сейчас уродливо

Есть: захват экрана/области/окна, DPI (2560×1600 физически), PNG, буфер обмена, хоткеи с
авто-запасным вариантом, часть инструментов.

Почему UI выглядит как «-15 из 10»:

1. **Нет сглаживания в принципе.** Всё рисуется голым GDI (`SetPixel`-подобные примитивы).
   Гди-линии без AA — это лесенка, поэтому «иконки как для Windows 98».
2. **Иконки нарисованы от руки пикселями**, без единой сетки, без оптической центровки,
   без состояний hover/active/focus.
3. **Кнопки Undo/Redo/Save реально невидимы:** они пишутся `DrawTextW` прямо в DC окна, а
   потом `render()` перекрывает всё окно своим холстом — текст затирается. Это баг, не задумка.
4. **Нет типовой системы**: размеры/отступы/радиусы подбирались на глаз в каждом месте заново.

Вывод, важный для порядка этапов: **сначала меняется слой рисования, потом инструменты.**
Красивый тулбар на текущем GDI-слое физически невозможен — сколько раз ни перерисуй.

## 1. Референсы (что считаем «лучше Яндекса»)

| Продукт | Что берём |
|---|---|
| CleanShot X | парящая «пилюля» аннотаций, привязанная к рамке; свойства инструмента всплывают контекстно; никакого оконного хрома во время захвата |
| Flameshot | инструменты прямо на оверлее, толщина/цвет в том же ряду; быстрый путь «выделил → подписал → скопировал» |
| Snagit | конфигурируемый тулбар: частые действия ближе, остальное в меню |
| ShareX | эффекты вывода: отступы, скругление, тень, фон — отдельная группа, не mixed с инструментами |
| Windows 11 Snipping Tool | спокойная светлая панель, крупные понятные иконки, минимум подписей |

Яндекс как эталон функционала (из их бинарника, `yd_research/FINDINGS.md`):
строка 20–22: `File | Edit | View`; `Arrows | Text | Shapes | Marker | Blur | Crop | Undo | Redo`;
второй ряд — подстили стрелок (прямая/ломаная/пунктир) и стили линий (сплошная/штриховые).
строка 29–30 (их ключи настроек = карта паритета параметров): `LineStyle, ArrowColor, Width,
FontName, FontSize, FontColor, TextBgColor, ShapeToolName, Color, OutlineColor, CropColor,
MarkerWidth, MarkerColor, TransparentAutoCrop, ArrowWidth, UnsavedAction`.
строка 33–34: у них есть `ToolbarPanel`, `ContextPanel`, `FooterPanel` — то есть панель
свойств и нижняя панель статусов; у нас их нет вообще.

## 2. Направление дизайна (решение, а не «чисто и современно»)

**Кто человек и задача:** ты снимаешь экран на рабочем столе с масштабом 175%, чтобы
объяснить проблему в чужом скрине. Цель — «выделил → подписал → отправил» за несколько
секунд, не изучая меню. Значит: оверлей без оконного хрома, инструменты под рукой, свойства
всплывают сами.

**Ощущение:** спокойный рабочий инструмент, как измерительный прибор, а не как игрушка.
Плоский, тёмно-нейтральный, с одной активной красной точкой.

**Токены (единая система, всё из примитивов):**

- Surface (повышения): `canvas #1B1D21` → `panel #24272D` → `floating #2C3037` → `menu #333841`.
  Один оттенок, меняется только светлота. Никаких разноцветных фонов.
- Границы: `rgba(255,255,255,0.07)` разделение, `0.12` акцентная, `0.20` фокус-кольцо.
- Текст 4 уровня: primary `#E9ECF1`, secondary `#A9B1BC`, tertiary `#7C8593`, muted `#5A6270`.
- Акцент один: `#E42A31` (цвет стрелки Яндекса, уже твой рабочий цвет) — только активный
  инструмент и подтверждение. Остальное — структура, не цвет.
- Сетка шага: 8 / 6 / 4. Высота контрола 32 (зона попадания 40), иконка 20×20 на сетке 24,
  радиусы: контрол 6, панель 10, всплывающее окно 12, модалка 16.
- Типографика: Segoe UI, масштаб 1.25 → 11 / 13 / 16 / 20; hierarchy весом и цветом, не размером
  (подпись 11/500/muted, значение 13/600/primary, заголовок 16/600).
- Глубина: **только границы + один мягкий слой тени** для парящих панелей. Один выбранный
  способ на весь продукт.
- Состояния обязательны у каждого контрола: default / hover / active / focus / disabled.

**Сигнатура (то, чего нет у Яндекса и что невозможно спутать с другим продуктом):**

1. **Измерение во время рисования.** Рядом с курсором — живой HUD: `2360×1400` и лупа
   с пиксельной сеткой 8× и перекрестием; рамка притягивается к краям окон и монитора.
2. **Пилюля свойств, привязанная к выделенному объекту.** Кликнул по стрелке — над ней
   всплывает узкая пилюля: цвет / толщина / стиль линии / удалить. Не модалка и не боковая панель.

Движение: только hover 120 мс и появление пилюли 160 мс (cubic-bezier(0.23,1,0.32,1)).
Хоткеи и повторные действия не анимируются вообще.

## 3. Этапы

### Этап 1. Слой рисования + дизайн-система (база для всего остального)

Что делается:
- Перевод рисования интерфейса на Direct2D + DirectWrite (сглаживание, скругления, кривые
  Безье, пунктирные штрихи, нормальный текст). Проверено: фабрики D2D и DWrite поднимаются,
  `libd2d1/libdwrite/libwindowscodecs` есть, API D2D 1.0 (`CreateHwndRenderTarget`,
  `CreateStrokeStyle`, `CreatePathGeometry`, слои, трансформации) доступен.
- Токены выше — в один заголовок, из которого рисуются **все** панели. Никаких хардкод-цветов
  в вызовах.
- Иконки 20×20 на сетке 24, вектором, оптически центрированы, 1.6px штрих, единый язык
  (скруглённые концы, одинаковая оптическая толщина). Иконки масштабируются под DPI 175%.
- Чинится невидимость Undo/Redo/Save: весь тулбар рисуется в один слой, никакого `GetDC`
  поверх холста.
- Состояния hover/active/focus на каждом контроле.

Артефакт приёмки: скриншот окна редактора на 175% — иконки читаемые, кнопки видимые,
подсветка активной кнопки, палитра и толщины аккуратные. Плюс скриншот в 2× увеличении,
чтобы видеть отсутствие лесенки.

### Этап 2. Оверлей выделения: UX вместо рамки

- Лупа-увеличение 8× с пиксельной сеткой и координатами под курсором.
- Живой HUD `ширина×высота`, табличные цифры.
- 8 ручек изменения размера + перетаскивание всей рамки, минимальный размер 8×8.
- Притягивание к краям окон и краям монитора (порог 6 px) с визуальной подсказкой.
- Пресеты: весь экран, текущий монитор, предыдущая область, окно под курсором.
- Строка подсказок: `Enter` подтвердить, `Esc` отмена, `C` повторить прошлую область.

Артефакт: скриншот оверлея с активными лупой и HUD; проверка рамки в самом углу экрана
(2560×1600) без обрезки.

### Этап 3. Паритет инструментов, часть A

Стрелка: подстили прямая / ломаная / пунктир (их `ArrowWidth`, `ArrowColor`).
Фигуры: прямоугольник и эллипс, отдельно заливка и обводка (`Color`, `OutlineColor`,
`ShapeToolName`), скругление угла как бонус.
Маркер: полупрозрачный выделитель (`MarkerColor`, `MarkerWidth`).
Текст: шрифт, размер, цвет, фон под текстом (`FontName`, `FontSize`, `FontColor`, `TextBgColor`).

Артефакт: один скриншот редактора, где показаны все четыре инструмента в работе, и таблица
соответствия их ключам настроек Яндекса.

### Этап 4. Паритет инструментов, часть B

- Размытие/пикселизация области (у них `blur_box.cpp`).
- Кадрирование: рамка + `CropColor`, авто-обрезка прозрачных краёв (`TransparentAutoCrop`).
- Стили линий сплошной / штриховые (`LineStyle`).
- Полноценная история Undo/Redo (глубина, не «сбросить один шаг»), Ctrl+Z/Y, Delete.
- Пилюля свойств по сигнатуре из раздела 2.

Артефакт: скриншот размытой области и кадрирования; тест Undo/Redo 10 шагов.

### Этап 5. Меню, статусы, настройки (то, что в их `File | Edit | View`)

- Файл: сохранить, сохранить как, копировать, открыть файл, отменить, закрыть.
- Правка: отменить/повторить, удалить, выделить всё, настройки.
- Вид: приблизить 100%/по размеру, тема, показ рамки выделения.
- Нижняя панель статусов (их `FooterPanel`): размер снимка, позиция выделения, масштаб.
- Окно настроек вместо правки `settings.ini`: хоткеи, куда сохранять, формат имени, тема.
- Открытие существующего файла (`ShotMvp.exe file.png`) — сейчас заглушка.
- Иконка в трее + меню, уведомление о сохранении с переходом к файлу.

Артефакт: скриншоты меню и окна настроек; проверка «открыл PNG → поправил → сохранил».

### Этап 6. Вывод и финальная полировка

- Реальное сжатие PNG и JPEG (сейчас файлы по 11 МБ из-за несжатых stored-блоков).
- Буфер обмена корректно: `CF_DIB` + `CF_BITMAP`, прозрачность при вставке в чат/документ.
- Эффекты вывода группой (как ShareX): отступ, скругление, тень, фон.
- Тема светлая/тёмная + слежение за акцентом Windows; DPI-масштабирование иконок и панелей.
- Ревизия производительности (окно не должно дёргаться при перетаскивании), автотест на каждый этап.

Артефакт: сравнение «до/после» размера файла и скриншот вставленного в документ изображения.

## 4. Порядок и почему именно такой

1 → база рисования, без неё любой тулбар остаётся «Windows 98».
2 → оверлей, потому что это самое частое действие (снимаю → отправляю).
3 → 4 → паритет по функциям, когда тулбар уже готов принимать инструменты.
5 → меню и настройки, когда инструменты уже не надо переставлять.
6 → вывод и полировка, когда ничего не ломается.

Этапы 1–2 нельзя менять местами. 3 и 4 можно дробить по одному инструменту за итерацию,
если тебе удобнее принимать чаще.

---

## 5. Как выглядит приёмка

После каждого этапа:
- скриншот реального окна приложения (не макет), снятый автоматическим тестом;
- вывод автотеста `ShotMvp_console.exe -selftest` (должен оставаться зелёным);
- список «что осталось на следующий этап».

Ты отвечаешь одно: принимаю / что переделать. Пока этап не принят, следующий не начинается.

## 6. Пакет релиза

Выпуск без приложенных бинарников не считается выпуском: тег есть, а взять нечего.

Обязательная часть каждого релиза (карточка #23):

- к тайгованному релизу приложены `ShotMvp.exe` и `ShotMvp_console.exe`, собранные из этого же
  коммита (`build.ps1` без `-Selftest`), с размером и контрольной суммой SHA-256 в теле релиза;
- имена файлов с версией (`ShotMvp-0.3.0.exe`), чтобы скачанный файл можно было отличить от
  скачанного вчера;
- сборка артефактов и их выкладка — шаг скрипта/CI, а не ручное «забыл прикрепить».

Косяк, который это чинит: релиз `v0.2.0` выпущен с `assets: []` — бинарников к нему нет.
