# Чеклист приёмки Easy-screenshot-tool

Владелец файла — tester. Пункт = проверка действиями живого пользователя, а не список фич.
Формат: `кто / где / действие → что видно глазами`. Пункт закрывается только если результат
видно глазами на реальной сборке. Протокол осмотра: экран 2560x1600 @ 175%, тёмная тема,
окна браузера и проводника частично перекрывают рабочий стол, в буфере обмена есть чужая картинка.

## Веха 0.2 — быстрый фикс-релиз

Объём вехи = карточки #1, #2, #3, #4, #5, #6, #7, #8, #9, #12, #19. Без своего пункта не осталась
ни одна из них — соответствие в таблице в конце раздела. Пункты 1–4, 10–13 и 20 проверяются как
регрессия уже принятого раньше поведения: карточкой 0.2 они не покрываются и новой работы от
разработчика не требуют.

### Захват

1. Пользователь / рабочий стол / сочетание клавиш захвата области (работает сразу после запуска
   приложения) → экран затемняется, появляется рамка выделения с подписью размера; после
   отпускания мыши открывается редактор со снимком этой области.
2. Пользователь / рабочий стол / оконный хоткей → снимок активного окна, редактор открыт на этом
   снимке, рамка окна не обрезана.
3. Пользователь / редактор / снять область в нижней и правой части экрана (до самых краев) → в
   редакторе видно ровно то, что было на экране; правый нижний край не срезан, размер в подписи =
   размер области в физических пикселях.
4. Пользователь / редактор / снять область через границу двух мониторов с разным масштабом →
   снимок не растянут и не сжат, картинка 1:1 к экрану.

### Панель инструментов

5. Пользователь / редактор / посмотреть на панель → у каждого инструмента и у действий вывода есть
   текстовая подпись рядом с пиктограммой (пиктограмма не вместо текста); группа инструментов,
   группа «Отменить»/«Повторить» и группа вывода различаются фоном поверхности контролов, а не
   только вертикальной чертой между ними.
6. Пользователь / редактор / выбрать инструмент «Маркер» и посмотреть на его значок по увеличенному
   листу `docs/icons/` и на самой панели → значок читается как маркер (колпачок и скошенная
   голова), а не как «просто линия» или прямоугольник; на снимке этот же инструмент рисует
   полупрозрачную подсветку.
7. Пользователь / редактор / посмотреть на значок «Кадрирование» по увеличенному листу `docs/icons/`
   и на панели → значок читается как рамка с вырезанным углом, а не как ломаная линия; на снимке
   этот же инструмент обрезает область.
8. Пользователь / редактор / посмотреть на значки «Отменить» и «Повторить» по увеличенному листу
   `docs/icons/` и на панели → дуги направлены в разные стороны (назад и вперёд) и не путаются местами;
   оба значка видны на панели, а не затираются холстом.
9. Пользователь / редактор / посмотреть на группу вывода по увеличенному листу `docs/icons/` и на
   панели → «Копировать» и «Сохранить» различаются глазами с обычного рабочего расстояния и по
   значку (два листа / диск со стрелкой), и по подписи; один и тот же значок не используется для
   обоих.
10. Пользователь / редактор / навести курсор на контрол → у контрола появляется подсветка; нажатие и
    отпускание внутри контрола не активирует соседний.
11. Пользователь / редактор / кликнуть по контролу, нарисованному слева от того, куда попала мышь →
    активен ровно тот контрол, под курсором которого находится кликабельная область.
12. Пользователь / редактор / кликнуть по свотчу цвета → у свотча появляется кольцо акцента, форма
    свотча не меняется, последующая линия этого цвета.
13. Пользователь / редактор / выбрать толщину → выбранный образец толще остальных, линия на снимке
    соответствует выбранной толщине.

### Текст

14. Пользователь / редактор / выбрать инструмент «Текст» и один раз кликнуть по снимку, отпустив
    кнопку мыши и убрав руку с экрана → в точке клика появляется курсор ввода; набранный с
    клавиатуры текст показывается на снимке по мере печати, рисовать мышью для появления текста не
    нужно.
15. Пользователь / редактор / набрать текст и нажать Enter → текст остаётся на снимке как готовая
    правка, поле ввода исчезает; после клика по другому инструменту текст всё ещё виден на том же
    месте.
16. Пользователь / редактор / начать новый текст, набрать его и нажать Esc → незафиксированный текст
    исчезает со снимка; раньше введённые и нарисованные правки остались на своих местах.
17. Пользователь / редактор / зафиксированный Enter’ом текст → «Копировать», затем вставить картинку в
    чат или графический редактор → текст виден на вставленном изображении ровно в том месте, где он
    был на снимке.
18. Пользователь / редактор / выбрать цвет текста и по очереди подложку «нет» / «светлая» / «тёмная» →
    текст читается на каждом из трёх вариантов; «нет» не рисует вокруг текста никакого прямоугольника;
    «светлая» и «тёмная» выглядят как разные фоны; смена цвета текста по свотчу меняет цвет надписи.

### Кадрирование и история правок

19. Пользователь / редактор / «Кадрирование», обвести область и подтвердить → снимок обрезан; затем
    Ctrl+Z → снимок вернулся к исходному размеру, кадрирования нет, все аннотации на своих местах и
    не потеряны.
20. Пользователь / редактор / после Ctrl+Z нажать Ctrl+Y → кадрирование возвращено: снимок снова
    обрезан по той же области, аннотации внутри неё целые.
21. Пользователь / редактор / нарисовать стрелку и овал, затем дважды Ctrl+Z и дважды Ctrl+Y →
    порядок отмен и повторов соответствует порядку действий.

### Вывод результата

22. Пользователь / редактор / «Копировать» → редактор не закрылся; в папке сохранения новый файл не
    появился (папка выглядит ровно как до нажатия); в буфере обмена изображение — вставка в чат или
    графический редактор даёт картинку с теми же размерами в пикселях, что показаны в полосе статуса
    редактора; лежавшая до этого в буфере чужая картинка заменена.
23. Пользователь / редактор (в настройках вывода выбран режим по умолчанию — «всегда сохранять в
    указанную папку») / первое «Сохранить» → приложение спрашивает папку; после выбора файл создан в
    ней и открытая копия соответствует снимку с аннотациями. Пользователь / редактор / «Сохранить»
    ещё два раза на двух других снимках → вопрос про папку больше не появляется, каждый новый файл
    виден в той же папке.
24. Пользователь / редактор (в настройках вывода заранее выбран второй режим — «всегда спрашивать
    место и имя») / «Сохранить» на двух разных снимках → каждый раз открывается окно выбора места и
    имени; после подтверждения файл виден в выбранной папке с выбранным именем; открытая копия
    соответствует снимку с аннотациями. Оба режима (23 и 24) проверяются глазами в одном прогоне.
25. Пользователь / редактор / посмотреть в нижнюю часть окна → полоса статуса не перекрывает снимок;
    между нижней рамкой снимка и верхней границей полосы виден свободный тёмный зазор, заметно
    больше прежних 6 px — по высоте в него умещается строка текста самой полосы; в полосе видны
    размер снимка в физических пикселях и подсказка по горячим клавишам.

### Сквозной поведенческий прогон

26. Владелец / редактор / один прогон на реальной сборке: снять область → текст (клик + печать с
    клавиатуры + Enter) → цвет и подложка → стрелка → овал → кадрирование → Ctrl+Z → Ctrl+Y →
    «Копировать» → «Сохранить» → открыть сохранённый файл и вставить буфер в чат → каждый шаг
    выглядит в окне ровно так, как описано в пунктах 5–25, а открытый файл и вставленная картинка
    совпадают с тем, что было на экране до последнего «Копировать»/«Сохранить» (включая текст).

## Вне приёмки 0.2

- Настройка горячих клавиш в самом приложении (прежний п.20) карточкой 0.2 не покрыта и из приёмки
  0.2 снята: в 0.2 проверяется только уже заданное сочетание, работающее сразу после запуска (п.1,
  п.2). Как пункт приёмки вернётся вместе с окном настроек.
- Контрол масштаба (прежний п.21 «увеличить/уменьшить масштаб, если контрол уже есть») — карточка
  #14, веха 0.3: см. п.28 ниже.
- Неактивное состояние «Сохранить», когда правок нет (docs/TOOLBAR-SPEC.md §2), держится на том же
  учёте несохранённых правок, что и пункт о закрытии редактора: проверяется в 0.2.1, п.36.

## Веха 0.2.1 — устойчивость раскладки и несохранённые правки

Объём вехи = карточки #24 (размер окна, DPI, аккуратная раскладка), #22 (учёт несохранённых правок),
#16 #17 #18 (открытие готового файла, сжатый PNG, манифест в сборке), #23 (бинарники в релизе).
Объём функциональности по сравнению с 0.2 не меняется: в этой вехе ничего не добавляется в тулбар,
перековывается то, что уже есть.

### Размер окна, перестроение панели, DPI

29. Пользователь / редактор / тянуть правую и нижнюю границы окна к центру с остановками не реже
    чем через каждые 150 px, потом вернуть обратно → на каждой остановке панель инструментов целиком
    внутри окна, полоса статуса видна под панелью и не накрыта ни панелью, ни снимком; свободная
    тёмная полоса под панелью и над снимком остаётся.
30. Пользователь / редактор / сузить окно до двух-трёх строк панели → количество контролов ровно то
    же, что в широком окне; подписи инструментов исчезают раньше, чем контролы уйдут за край;
    порядок групп (инструменты → цвета → свойства → история → вывод) не меняется, черта-разделитель
    между группами остаётся; контрол кликабелен ровно там, где нарисован (клик по нарисованному
    контролу активирует его, соседний — нет).
31. Пользователь / редактор / низкое окно (панель + полоса статуса почти на всю высоту) → панель и
    полоса не наезжают друг на друга; снимок обрезан по своей полосе — его край виден целой рамкой,
    а не ушёл под панель или под полосу; начать рисование вне видимой полосы нельзя.
32. Пользователь / редактор / пытаться сжать окно дальше предела → границы останавливаются; в этом
    минимальном размере панель занимает почти всю ширину окна, все контролы на месте, полоса статуса
    видна целиком.
33. Пользователь / редактор / перетащить окно на монитор с другим масштабом (или сменить масштаб
    на том же мониторе) → панель, снимок и полоса перестроены под новый масштаб: контролы одного
    размера на всей панели, подписи не обрезаны, размер в полосе статуса по-прежнему равен размеру
    снимка в физических пикселях, ничего не уехало за край окна.
34. Владелец / редактор / сквозной прогон пункта 26 в окне не по умолчанию (например 1100×900 и
    минимальном размере) → каждый шаг выглядит так же, как описано в пунктах 5–25; нигде не видно
    обрезанной подписи, контрола без пиктограммы и наезда полос.

### Несохранённые правки (п.27 перенесён сюда из вехи 0.3 без изменения номера)

27. Пользователь / редактор / есть несохранённые правки и закрытие редактора (крестик или `Esc`) →
    приложение задаёт явный вопрос с тремя вариантами «Сохранить / Не сохранять / Отмена»; «Не
    сохранять» ничего не пишет на диск (в папке сохранения новый файл не появляется) и редактор закрыт;
    «Отмена» оставляет редактор открытым с правками на месте и ничего не пишет; «Сохранить» закрывает
    редактор и создаёт файл, открытый файл = снимок с правками; пока правки не выведены, в подписи
    группы вывода видно «есть несохранённые правки».
35. Пользователь / редактор / снять область и сразу закрыть редактор крестиком или `Esc` (правок нет)
    → вопрос не появляется, окно закрыто, в папке сохранения новый файл не появился.
36. Пользователь / редактор / снять область и посмотреть на группу вывода, не рисуя ничего →
    «Сохранить» выглядит неактивным (как «Отменить» при пустой истории), `Ctrl+S` в этом состоянии
    ничего не пишет; после первой нарисованной правки «Сохранить» становится обычным контролом, а в
    подписи группы вывода появляется «есть несохранённые правки»; размер и форма панели при этом не
    меняются.
37. Пользователь / редактор / правка, затем «Копировать» → подпись группы вывода снова «чистая»
    (несохранённых правок нет), закрытие больше не спрашивает; «Сохранить» при этом остаётся обычным
    контролом — документ всё ещё отредактирован.

### Открытие файла, вес PNG, состав релиза

38. Пользователь / проводник / «Открыть с помощью» → ShotMvp.exe для готового PNG (или та же строка
    в командной строке) → редактор показывает именно этот файл: размер в полосе статуса = размер
    файла в пикселях, пиксели совпадают с оригиналом; после правки и её отмены `Ctrl+Z` «Сохранить»
    пишет открытую копию, которая совпадает с оригиналом по всем пикселям.
39. Пользователь / редактор / снять весь экран, нанести правку и «Сохранить» → вес полученного файла
    заметно меньше веса сырых пикселей этого кадра (кадр 2560×1600 не весит ≈12 МБ); открытая копия
    читается в обычном просмотрщике Windows.
    Права 38 и 39 начинаются с правки потому, что с карточки #22 «Сохранить» живой контрол только
    когда документ отличается от снятого кадра (п.36); снятый кадр без правок сохранить нельзя —
    этот UX-долг заведён отдельной карточкой (#25), в 0.2.1 поведение остаётся таким, как принято
    в #22.
40. Владелец / GitHub / страница релиза `v0.2.1` → к релизу приложены `ShotMvp-0.2.1.exe` и
    `ShotMvp_console-0.2.1.exe`, скачанный exe запускается без установки и даёт все пункты 0.2 и
    0.2.1 этого чеклиста; размер и SHA-256 каждого файла напечатаны в теле релиза.

## Метрика

Escape rate: сколько дефектов найдено проверками до релиза против сколько найдено владельцем после
релиза (цель ≤ 2). Каждый дефект владельца порождает: пункт этого чеклиста, регрессионный автотест
и запись в памяти проекта. Ссылка на «сколько прогонов сделано» как показатель качества запрещена.
